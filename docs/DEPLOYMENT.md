# Развертывание первого пилота

## Что уже есть

Репозиторий содержит backend-миграции, Telegram server adapter и web-кабинет. Он не содержит секретов и не подключается к чужим данным.

## Нужны от владельца проекта

1. URL проекта, publishable key и service role key — только в secret store развертывания.
2. Перевыпущенный Telegram bot token перед production-запуском. Токен не добавляется в Git, n8n или клиентский JavaScript.
3. Решение, кто будет первым `OWNER`, и 2–3 тестовых водителя для пилота.

## Порядок запуска

1. В новом Supabase-проекте выполнить по порядку:
   - `supabase/migrations/00001_initial_schema.sql`;
   - `supabase/migrations/00002_telegram_workflows.sql`;
   - `supabase/migrations/00003_owner_web.sql`;
   - `supabase/migrations/00004_organization_bootstrap.sql`;
   - только для тестовой среды: `supabase/seed/demo.sql`.
2. Проверить, что bucket `expense-receipts` остался private. Водитель не получает service role key и не ходит в БД напрямую.
3. Настроить URL конфигурации Auth: development URL и redirect URL `<домен>/auth/confirm`.
4. Развернуть Next.js-приложение, задать переменные из `.env.example`, зарегистрировать первого пользователя через `/register` и создать компанию через `/onboarding`. Функция `bootstrap_organization_with_owner(...)` создаёт tenant, membership `OWNER` и системные категории расходов одной транзакцией.
5. Добавить машины, водителей и активный рейс через web-кабинет.
6. Для каждого водителя создать `telegram_driver_invites`: в БД хранится только SHA-256 хеш случайного одноразового кода; водителю отправляется deep link `https://t.me/<bot>?start=<code>`.
7. Выполнить `npm run bot` отдельным process рядом с web-приложением.

## Telegram-гарантии

- `/start <code>` привязывает Telegram ID только к заранее созданному водителю;
- `telegram_update_logs` не даёт обработать update повторно и разрешает контролируемый retry только после `FAILED`;
- запись расхода, одометра и статуса проходит через серверные SQL-функции, которые проверяют организацию, водителя и активный рейс;
- чек загружается в private Supabase Storage и сохраняется отдельным attachment;
- Telegram показывает водителю только его рейс и его предварительную зарплату, не внутреннюю прибыль компании.

## Роль n8n

n8n подключается после запуска ядра как интеграционный слой: напоминания о ТО, уведомления о задержке, подтверждённый импорт из Sheets и отправка ежедневной сводки. Он не хранит диалоги бота, P&L или права доступа.

## Критерий первого пилота

Один собственник создаёт машину и многоплечевой рейс; водитель привязывает Telegram по invitation, добавляет топливо/чек, пробег и статус; менеджер вносит доход; dashboard показывает согласованный P&L, себестоимость/км, прибыль/км и порожний пробег.
