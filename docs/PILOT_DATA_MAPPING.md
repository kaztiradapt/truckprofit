# KAZ-TIR и Joldas: карта пилотных данных

## Что подтверждают реальные таблицы

### KAZ-TIR_Операционная

Лист `trips` уже содержит полезные факты: `trip_id`, дату, тип `expedition/own`, города, маршрут, км, статус, менеджера/логиста/диспетчера, выручку, машину, топливо, прочие затраты, total cost, margin, оплату и дебиторку. Это подтверждает необходимость различать рейс, стоимость, доход и cash/payment status.

Но текущая строка рейса не заменяет новую модель: нет нормализованных `TripLeg`, статуса `loaded/empty` по плечу, журнала одометра, детализированных расходов, правил зарплаты, tenant isolation и неизменяемого аудита.

### 2026 Joldas Logist

Листы `Доходы`, `Расходы`, `Зарплата`, `P&L`, `Налоги` подтверждают отдельные контуры управленческой экономики: доход, расход, зарплата, месячный P&L, налоговая оценка. В доходах уже есть машина, маршрут, вес, объём, выручка, примерная себестоимость и прибыль; в расходах — категория, сумма, машина и источник.

Но данные агрегированы и частично ручные: строки зарплаты месячные, расходы не всегда привязаны к рейсу/одометру, P&L не является набором проверяемых первичных событий. В продукте эти листы становятся результатом вычисления, а не таблицами ввода.

## Маппинг при будущем импорте

| Пилотное поле | Целевая сущность | Ограничение |
|---|---|---|
| `trips.trip_id` | `trips.external_reference` | не использовать как глобальный PK SaaS |
| города/маршрут/км | `trip` + один предварительный `trip_leg` | loaded/empty неизвестны — пометить `UNKNOWN` |
| `truck`, `Авто` | `vehicles.external_reference` | ручной дедуп по номеру/идентификатору |
| выручка/Доходы | `incomes` | payment status переносить отдельно |
| fuel/extra cost/Расходы | `expenses` | категория/дата/vehicle должны пройти validation |
| водитель/Зарплата | `drivers`, `driver_compensation_calculations` | историческая сумма не создаёт правило оплаты |
| kpn/Налоги | `tax_profiles` + estimated tax result | не считать бухгалтерским фактом |

## Правило импорта

Первый импорт — только копия, только в demo/pilot organization, с import report: создано, пропущено, неоднозначно, требует review. Автоматическая запись в рабочие Google Sheets или обратная синхронизация не входят в MVP.
