# Безопасность TruckProfit

## Изоляция компаний

- Каждая рабочая запись содержит `organization_id`; доступ браузера ограничивается PostgreSQL Row Level Security.
- Клиент использует только публичный ключ Supabase. `service_role`, Telegram token и OpenAI key разрешены только серверным модулям.
- Сотрудник может назначать только те права, которыми обладает сам. Совладельца назначает только основной владелец.
- Удаление записей требует отдельного права `DELETE_RECORDS`; основной владелец защищён от изменения и удаления.
- Таблицы компании закрыты от роли `anon`, внутреннее состояние Telegram закрыто и от прямого доступа `authenticated`.

## Файлы и внешние сервисы

- Чеки и вложения поддержки хранятся в приватных Storage buckets и открываются краткоживущей подписанной ссылкой.
- Перед подписью сервер проверяет компанию, запись, bucket и полный формат object path.
- В OpenAI уходят только данные, необходимые для отчётного вопроса. Чеки, контакты, Telegram ID, адреса и геопозиции исключены; хранение ответа провайдером отключено (`store: false`).

## Обязательные действия перед пилотом

1. Включить MFA в Supabase, Vercel, GitHub и Google-аккаунте владельца.
2. Сменить Telegram bot token, если он когда-либо отправлялся в чат или показывался на экране. После смены обновить переменную Vercel и webhook.
3. Не копировать `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `OPENAI_API_KEY` в браузерный код, логи, скриншоты или обращения поддержки.
4. Применять миграции по порядку и проверять `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` перед production deploy.
5. До коммерческого запуска определить срок хранения чеков, обращений поддержки и геолокаций, а также процедуру удаления данных клиента.

## Проверка инцидента

При подозрении на утечку: немедленно отключить затронутый доступ, сменить ключ, сохранить audit/log evidence, определить организации и записи в зоне риска, уведомить ответственного и только после устранения вернуть интеграцию в работу.
